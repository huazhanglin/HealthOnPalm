# AI 辅助开发实战（二）：开工前，我给项目配了一条"三 AI 工具链"

> 系列第二篇。上一篇讲了三个 AI 的分工（龙虾规划 / 科泽执行 / 千问排障），这篇讲落地：每个工具怎么选、怎么配、哪些 Key 必须立刻记录、以及一套可直接复制的立项提示词模板。全部是我项目里的实际配置，Windows 环境。

## 一、工具链选型与配置

### 1. 龙虾：项目规划者（免费）

我在 Windows 下经腾讯 QClaw 使用，免费。选型标准只有一条：**能做项目规划、能给分步指导**。

实操建议：别一上来就说"帮我做个 App"。先用一个小场景把它用熟——我是拿它当健身教练用了一段时间，知道它擅长什么、怎么回答之后，才让它规划项目的。冷启动直接谈大项目，往往聊不出深度。

### 2. 科泽（Cursor）：代码生成车间（Pro 约 150 元/月）

cursor.com 注册下载。本质是内置 AI 的 VS Code。免费版有限制，正经做项目建议直接上 Pro。

装好后验证链路：打开右侧聊天面板，随便问一句，有回复即通。

只需要用三个功能：**对话面板**（讨论需求）、**代码生成**（AI 直接改文件）、**命令执行**（AI 自己跑测试）。其余功能全部忽略，学习成本为零。

### 3. 千问：排障顾问（免费，Windows 客户端）

定位明确：**不写整个项目，只救火**。Cursor 里修不掉的报错、页面故障，带过来换模型换视角。

### 三工具联动验证（5 分钟）

装完先跑一遍最小闭环：

1. 对龙虾："我想做一个记录每天喝水量的手机 App，帮我出个最简单的分步计划。"
2. 挑最小任务（如"设计存水的数据库表"）复制进科泽（Cursor），让 AI 写出来。
3. 对千问："我完全不懂数据库，像对一个外行一样解释一下什么叫'表'。"

走完即验证了完整分工：**龙虾规划 → 科泽动手 → 千问答疑。**

## 二、四个账号的关键配置项

### Supabase（数据库 + Auth + 接口托管）

创建项目时的三个决策点：

- **区域选 Singapore**，国内访问相对稳定
- **数据库密码随机生成后立刻存密码管理器**——这个丢了很麻烦
- 初始化完成后，到 项目设置 → API 记录三样：**Project URL、Anon Key、Service Role Key**

安全红线：**Service Role Key 是最高权限钥匙，只能用在后端（Edge Functions），绝不能进前端代码。**

控制台四个高频区域先认识：Table Editor（表）、Authentication（登录）、SQL Editor（建表语句）、Edge Functions（后端接口）。本章只需认识，无需操作。

学习阶段免费额度够用。

### SiliconFlow（大模型 API）

选聚合平台的原因：**一个 API Key 覆盖全家桶**——

- 对话：DeepSeek-V3（晨报、问答生成）
- 向量：bge-m3（AI 记忆，RAG 检索用）
- 语音：SenseVoice（识别）+ CosyVoice2（播报）

充值 50 元起步。API Key 不能泄露、不能明文写进代码。

### HBuilderX + Apple Developer

关键认知：**日常代码在科泽（Cursor）里写，但真机调试和打包上架必须走 HBuilderX**——uni-app 项目编译成 iPhone 可安装应用这一步，没有替代品，命令行工具替代不了。免费下载。

Apple Developer 付费账号（年费）：TestFlight 分发必需。不涉及真机硬件的项目可先用模拟器/H5 预览，暂缓注册。

### GitHub（可选）

建议尽早用上，防丢代码。

## 三、立项提示词模板（可直接复制）

我的立项走了三步，每步对应一个模板：

**第一步，对龙虾要方案：**

```
我最近在用你做XX（你的使用场景），遇到的问题是XX（具体的不方便）。
我希望有一个手机 App 能XX（你的期望）。
你觉得技术上可行吗？请给我几个方案设计，说明每个方案的优缺点。
```

**第二步，对其他 AI 交叉评审：**

```
我准备做一个 App，核心功能是XX。
另一个 AI 给了我这个方案（贴上方案内容），
请你从你的角度评审一下：有没有漏洞？有没有更好的做法？
```

**第三步，回龙虾落计划：**

```
综合各方意见，我们确定方案如下：XX。
请把它落成一份分周分步的执行计划，
每周有明确交付物，每天的任务要具体到我当天能直接动手做。
```

**为什么要交叉评审？** 我的教训：项目中途从微信小程序改成 iOS App，就是因为"小程序无法访问 HealthKit"这个硬伤在方案期没被发现。纸面上推翻方案成本几分钟，写到一半推翻成本几天。多模型交叉评审是成本最低的方案防御手段。

## 四、日常开发循环

每天四拍：

1. **对龙虾**："昨天完成了XX，今天该做什么？"→ 得到当天任务
2. **按指导动手**：龙虾的指导细到工具级——在科泽（Cursor）输入什么提示词、在 Supabase 点哪个菜单
3. **卡住找千问**：贴报错代码，或直接截故障页面问"为什么出现这样的故障，怎么解决"
4. **回龙虾汇报**："XX 做完了，YY 超时了" → 它校准后续计划

核心价值：**开发者永远不需要自己决策"接下来该干嘛"**——规划被外置给了龙虾，你只负责执行与验收。
