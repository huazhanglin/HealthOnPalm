# 我用 AI 造 App（七）：终章——一周没写一行产品代码，和一份可带走的 OPC 清单

系列第七篇，也是终章。前六篇讲了立项、AI 分工、数据库、假数据、自研插件接真数据、训练闭环（文末有链接）。这一篇收两个尾：**第五周——整整一周，没有一行产品代码**；以及把全书七章撞过的问题，浓缩成一张问题图、七条规矩、一笔总账。

## 这一周做成了什么

一句话：没有一行产品代码、没有一条新迁移、没有一个新的 Edge Function。第五周是文档周——改施工稿、对码、证明"没做"、写执行记录。

听起来不像开发周？恰恰相反。这一周干的事，决定了前面六周的记录还能不能信。往下看。

## 一、施工稿的保质期：一本会撒谎的说明书

翻出第三章的执行计划，白纸黑字写着："微信小程序、微信登录或手机号 OTP、Supabase 后端"。真实交付是：iOS App、邮箱密码登录。后端从头到尾是 Supabase，没换过——对不上的只有"端"和"登录"两处，但这两处足以让一份说明书变成一本会撒谎的说明书。

不止 W1。W2 计划里训练闭环写得像当周要交付，实际 W4 才做；W3 计划把基础代谢列进插件清单，实际当周根本没查。

处理方式：不改历史正文，给 W1/W2/W3 三份计划文首各加一张"实际运行对照"表，验收标准改为"以对照为准，而非过期的 Day 任务"。

| 计划 | 实际运行对照 |
|---|---|
| W1 | 主端是 iOS App 不是小程序；登录是邮箱密码；代码在 uni-app/ |
| W2 | 晨报 + Agent 已真机跑通；无定时推送；Workout 是文案级；恢复分细则在 W4 重做 |
| W3 | 插件路径在 uni-app/src/uni_modules/；当时是三 Tab；基础代谢当周未查；自动同步在 W4；种子表空 |

立下的规矩一句话：**计划文档和执行记录是两种东西，前者是意图，后者是事实；意图允许落空，事实不允许掺水。**

## 二、对码：给书稿做一次事实核查

"对码"这个词借自工程验收：设计图和实体建筑逐条比对。这一周把书稿六章里所有机制描述，和真实代码、真实数据库逐条比了一遍。抽查出来的硬规则，几条最典型的：

- 注册建档：前端 register() 只做 signUp，不直接 insert；插行的是数据库触发器 handle_new_user()（SECURITY DEFINER），挂在 auth.users 的 INSERT 上。触发器的 SQL 在 W1 的 T2.3 任务文档和 Dashboard 里，不在 supabase/migrations/。
- 嵌入维度：W1 建表时 content_embedding 是 VECTOR(1536)，后来切到 SiliconFlow 的 bge-m3 模型，ALTER 成 1024。
- 记忆窗口：MAX_MESSAGES = 20，摘要阈值 12。
- 供应商切换：OpenRouter → SiliconFlow 发生在 W2 部署时。

对码最值钱的产出是改错。第六章 v1 就被改出四个硬错：exercise_ids 列不是 W2 预留的，是 W4 建动作库时才加的；心情写死 normal 按 W2 公式是 5 分，不是 8 分；LLM 的围栏是 160 条 featured，不是 860 条全库；P0 第九项是"SQL 已执行"，不是说明书。

这些错没有一个是 AI 胡编的，全是"我们共同的想当然"。对码防的不是胡说，是想当然。

## 三、证明"没做"，也需要证据

"第五周没写产品代码"这种话，说出口就得有证据。2026-08-26 复查，全部与 W4 结束时相同：

| 项目 | 状态 |
|---|---|
| 底部导航 | HomeTabBar.vue 函数名叫 switchTab，实现是 uni.redirectTo |
| 原生 tabBar | pages.json 无 tabBar 配置 |
| 数据库迁移 | 最新仍是 20260821_healthkit_recovery_metrics.sql（W4） |
| HealthKit 类型 | 无血压；临床类仍不读 |
| 种子追踪表 | 用户行空白 |
| git | 仅 13263c5 一个 commit，其后全部在工作区 |

有个细节值得单说：HomeTabBar.vue 里那个 switchTab 是组件自己的本地函数名，不是 uni-app 的 uni.switchTab API——名字先改了，实现还是 redirectTo。不看代码，光看函数名就会得出"导航已经换好了"的结论。

## 四、13263c5：一个只有一个 commit 的仓库

这个项目唯一的 commit 停在 2026-08-10，覆盖 W1–W3。W4 全部产品代码、W5 全部文档和书稿，都在工作区里，一次都没提交。写下这段话的 08-26，距离那个 commit 约 16 天。

风险两条：没有版本历史就没有后悔药；没有提交纪律就没有交付边界。W6 候选清单第一行已经写好了：把 W4 起未提交的代码与文档入库。

## 七、全书小结：七章，一张问题图

七章写完，把每一章撞上的问题和留下的规矩排成一张表（冻结日 2026-08-26）：

| 章 | 撞上的问题 | 留下的规矩 |
|---|---|---|
| 一 | 不会写代码的人，要做一个能用的 App | 人定约束，AI 执行 |
| 二 | 模型会自信地给错方案 | 交叉评审；在纸上推翻，比在代码里推翻便宜 |
| 三 | 计划小程序/OTP，交付 iOS/邮箱；触发器不在 migrations | 容器先于内容；权威来源只有一处 |
| 四 | 先上真传感器会耗死项目；1536→1024；Safety 不能只靠正则 | Mock 先行；基础设施要人验证；文档先行少走弯路 |
| 五 | HealthKit 小程序不可达；插件 vs 自研；读权限无 denied 回执 | 人验证前置条件；没发出去就不算做完 |
| 六 | 昨天的数据、redirectTo、恢复分三桩冤案、证书混用 | 做对先于做多；砍掉的任务也要有清单 |
| 七 | 计划会过期；印象会写错书；git 停在 W1–W3 | 对照不涂历史；对码；没做要有证据；commit 是存档 |

## 八、七条 OPC 规矩

1. **AI 给选项，人做决策。** 三次推翻（小程序改 iOS、第三方插件改自研、OpenRouter 改 SiliconFlow），合计花了约 8–10 小时——但每一次推翻都比将错就错便宜。
2. **计划是地图，执行记录是轨迹。** 意图允许落空，事实不允许掺水；过期地图不可怕，可怕的是它看起来还像新的。
3. **先假数据，再真传感器。** Mock 让逻辑先转起来，真数据只负责暴露 Mock 糊弄过去的问题。
4. **克制写在"不做什么"上。** 不诊断、不给组数重量、不读临床数据——一个健康 App 的边界，不在功能列表里，在拒绝清单里。
5. **同一份计算，只许存在一份代码。** 两个函数各算各的恢复分，迟早改一处忘一处。
6. **"跑通"和"发出去"是两条验收线。** 这个项目至今只跨过了第一条——闭环在转，但只在开发者自己的手机上转。
7. **账本和 git 都是写给未来的自己。** 有数字记数字，没记就写没记；做完要入库，否则"做完"只是心情。

## 九、总账

约 6.5 周，净投入约 71 小时，AI 参与度约 73%，API 花费约 ¥80 级（基础设施全在免费层）。产品停在约 0.3.8 / versionCode 138：五个 Tab、真数据晨报、训练打卡闭环、心情进恢复分、缓存与自动同步——一个能转的闭环，但主要还只在开发者自己的手机上转。

两个"还没发生"：陌生人种子反馈一份未归档（追踪表至今空白）；唯一 commit 仍是 13263c5。

## 十、三层债，不打包票

**过程债**（不依赖任何人，只依赖你打开终端）：把 W4 起未提交的代码与文档 commit 进去。

**产品债**（用户能撞上的墙）：原生 tabBar + switchTab，告别 redirectTo 闪页；把 TestFlight 链接发给真人，开始填追踪表——扩面不是增长动作，是"第一次听到难听话"的动作。

**能力债**（可以再晚）：Sleep Insight Agent、Weekly Review Agent、血压等生活方式指标、支付/订阅、上架材料，各有各的"还不到时候"。

三层之间的顺序原则：先拆用户会撞上的墙，再开新的能力；而在拆墙之前，先让仓库配得上"做完了"三个字。

最后一个常见问题，也是被问得最多的一个——**照这套方法做完一遍，我的 App 就能上架了吗？** 还不能，而且书里没打算教到那一步。你能得到的是一个能转的 MVP 闭环，距离上架还缺至少三样：真实种子的反馈（追踪表还是空的）、原生导航（tabBar 还没换）、上架材料与隐私标签。从闭环到上架之间那段路，得用真实用户的难听话铺。
