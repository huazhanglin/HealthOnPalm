## 二、W4-T2 今日训练计划闭环

### 目标

把 W2 的 Workout Agent 从「文案建议」做成：**精选库出题 → LLM 只许选 ID → 写入当日 `daily_summaries.ai_plan` → 用户打卡进 `workout_logs`**。

### 产品规则（Edge）

- 只能从候选清单选 `[id]`，禁止编造。  
- 恢复分 &lt; 50 或 `rest`：只许 light / 热身 / 拉伸。  
- 50–80 或 `light`：以 light/moderate 为主。  
- &gt; 80 或 `train`：正常强度，仍不编造。  
- **不给具体重量 / 组数 / 次数**（产品边界：非医疗、可执行）。  
- 结构：热身 1–2 + 正式 3–5 + 拉伸 1–2。  
- 计划缓存当日 `ai_plan` JSON；`force_refresh` 可重生成。

### 前端

- 新页 `pages/workout/plan.vue`：摘要（标题、理由、时长、热量、恢复分）、动作详情（肌群、器械、说明、署名）。  
- **完成并打卡**：`source = ai_suggested`，写入 `exercise_ids`，并 `invalidateFresh(home)`。  
- **重新生成** / **手动记录**。

## 六、W4-T6 恢复分规则重做

共用模块：`supabase/functions/_shared/recovery.ts`（`recovery-score` 与 `morning-brief`）。

维度不变：**睡眠 40 + 休息 30 + 活动 20 + 心情 10 = 100**。

### 1）无真实睡眠

- **不再**用 Mock 睡眠小时，也**不再**打 0 分。  
- 睡眠维给中性分 **32/40（80%）**，`sleep_missing = true`。  
- 首页文案：**「睡眠数据缺失，恢复分仅供参考」**。

### 2）休息平衡

取较高者：

- 连续无训练天数 × 10，封顶 30；  
- 近 7 天休息天数映射（≥2 天休息可到满分档），避免「练 7 休 2」在训练日被打成 0。

连续 / 周休息天数来自真实 `workout_logs`。

### 3）心情

见 T5；不再写死。

### 关键文件

- `supabase/functions/_shared/recovery.ts`  
- `supabase/functions/recovery-score/index.ts`  
- `supabase/functions/morning-brief/index.ts`

## 七、W4-T7 首页缓存（Tab 切回不再每次全量刷）

### 原因

`HomeTabBar` 使用 `redirectTo`，回首页会销毁页面，内存态清空，原先 `onShow` 必打晨报 + `fetchHomePageData`，体感慢。

### 做法

1. Pinia `stores/home.ts`：按用户 + **本地日期**保存简报与指标。  
2. 首页 TTL **5 分钟**：新鲜则秒开不请求。  
3. 过期但有快照：先展示旧数据，再静默刷新（简报只读库，不重新生成）。  
4. 记录运动 / 睡眠 / 心情、HealthKit 同步后 `invalidateFresh('home:…')`。  
5. 跨日或换用户：丢弃快照（登出 `user.clearLocalAuthState` 会 `home.clear()`）。  
6. 用户点「刷新」仍 `force: true`（并走 T8 同步）。

未改成原生 `tabBar` + `switchTab`（需要图标与 `pages.json` tabBar，留后续）。

### 关键文件

- `uni-app/src/stores/home.ts`  
- `uni-app/src/utils/freshness.ts`（`HOME_DATA_TTL_MS = 5min`）  
- `uni-app/src/pages/index/index.vue`  
- `uni-app/src/stores/user.ts`

## 八、W4-T8 HealthKit 自动同步与跨日

### 问题

首页只读云端，**不会自动从手机拉今日数据**；App 跨日保活时可能把昨日简报当成今日。用户今早看到的仍是昨天。

### 规则

| 时机 | 行为 |
|------|------|
| 进入首页 | 距上次同步 ≥ **30 分钟**，或 **已跨本地日** → 自动读 HealthKit 并上传 |
| 进入授权 / 同步页 | 同上 |
| 生成 / 刷新晨报 | **先强制同步**（60 秒内刚同步过则跳过，避免连打两次） |
| 手动刷新 | 立即同步 |

跨日：丢掉昨日 Pinia / 页面内存，再同步。

`sync-healthkit` 在 payload 缺 `date` 时改为 **Asia/Shanghai** 的今日，避免 UTC 把凌晨写成昨天。

### 关键文件

- `uni-app/src/lib/healthkit/index.ts`（`needsTodaySync` / `ensureTodaySynced` / `HEALTHKIT_AUTO_SYNC_TTL_MS`）  
- `uni-app/src/api/agent.ts`（`getMorningBrief` 前 `ensureTodaySynced({ force: true })`）  
- `uni-app/src/pages/index/index.vue`  
- `uni-app/src/pages/healthkit/authorize.vue`  
- `supabase/functions/sync-healthkit/index.ts`

## 十、W4-T10 HealthKit 读取扩展

### 问题

用户感觉「没有拿到苹果健康里的全部数据」。W3 只读活动环相关一小部分，且：

- `basalCalories` 有字段、**原生从未 query**（首页常为 0）；  
- 距离只累加 Workout，没有 **步行+跑步距离**。

### 原则

补齐 **活动 / 睡眠 / 心肺恢复** 中 HOP 用得上的类型。  
**故意不读**：病历、化验、用药、经期、饮食日记等临床数据。

### 读取类型（`DEFAULT_READ_TYPES` / Swift `defaultReadTypeIds`）

| 类型 | 说明 |
|------|------|
| StepCount | 步数（原有） |
| ActiveEnergyBurned | 活动热量（原有） |
| **BasalEnergyBurned** | 基础代谢（修好） |
| AppleExerciseTime | 锻炼分钟（原有） |
| **DistanceWalkingRunning** | 步行+跑步距离 |
| **FlightsClimbed** | 爬楼 |
| AppleStandHour | 站立（原有） |
| SleepAnalysis | 睡眠；**补浅睡/核心睡眠** |
| RestingHeartRate / HeartRate | 静息、平均；**补最高心率** |
| **WalkingHeartRateAverage** | 步行心率 |
| **HeartRateVariabilitySDNN** | HRV |
| **OxygenSaturation** | 血氧 |
| **RespiratoryRate** | 呼吸频率 |
| **VO2Max** | 最近一条（非仅今日） |
| Workout | 运动课（原有） |

无 Apple Watch 时 HRV / 血氧 / VO₂ Max 等为 `--` 属正常。

### 已授权用户

`HEALTHKIT_READ_TYPES_VERSION = 2`。版本落后时同步前会再走一遍 `requestAuthorization`（系统只弹**新增类型**）。用户需在系统弹窗中全部允许。

### 库表

`supabase/migrations/20260821_healthkit_recovery_metrics.sql` 为 `daily_summaries` 增加：

`max_heart_rate`、`walking_hr_avg`、`hrv_ms`、`spo2_percent`、`respiratory_rate`、`flights_climbed`、`vo2_max`。

首页「更多」与授权页预览同步展示。隐私文案已更新（`manifest.json` `NSHealthShareUsageDescription`）。

### 关键文件

- `uni-app/src/uni_modules/health-agent-healthkit/utssdk/app-ios/HealthKitBridge.swift`

## 十一、W4-T11 真机基座证书（过程记录）

### 现象

HBuilderX（Windows）重打自定义基座后，真机安装失败：

- 标准基座不能跑 UTS（提示，不是根因）；  
- 自定义基座 SDK 与当前 HX 可能不一致（警告）；  
- **证书配置错误** → 安装失败。

### 根因

云打包「制作自定义调试基座」时选了 **TestFlight 用的发布证书**，不是 **开发证书**。

| 场景 | 证书 |
|------|------|
| USB 自定义调试基座 | **iOS Development** + Development profile（含本机 UDID） |
| TestFlight / 上架 | **Distribution** + App Store profile（不需要 UDID） |

删掉手机上的 TestFlight 包**不是**原因。改回开发证书重打基座后恢复。当前 App 版本约 **0.3.8 / versionCode 138**（以 `manifest.json` 为准）。
