## 二、W5-T2 技术细节对码（服务书稿，不改产品行为）

书稿写作中按仓库核对过、且应写进对外叙述的事实如下（**未因此改 Edge / 客户端逻辑**）。

### 注册建档

- 前端 `register()` 只 `signUp`，不直接 `insert public.users`。  
- 设计是 `auth.users` INSERT → 触发器 `handle_new_user()`（`SECURITY DEFINER`）。  
- 触发器 SQL 在 **W1 T2.3 / Dashboard**，**不在** `supabase/migrations/`。  
- 引导完成时 `update` 失败则 `upsert`（兼容触发器未生效）。  
- W1 建表 `content_embedding` 为 **VECTOR(1536)**；切 SiliconFlow `bge-m3` 后 **ALTER 为 1024**（W3 起点表确认已执行）。

### 新手引导

- 五步：欢迎 → 健康档案（年龄/身高/体重）→ 运动偏好 → 数据授权（本页不调系统框）→ 完成。  
- `onboarding_completed` 存在，是整段是否完成的门禁。  
- **步骤内无云端草稿**；杀掉 App 从欢迎页重来，不是断点续填表单。

### W2 口径（写第二周请用当时公式）

- Mock 按运动水平生成步数/睡眠/心率等。  
- 恢复分当时：睡眠 40 + 连续休息 30 + 活动 20 + 心情 10；心情档曾为 10 / 7.5 / 5 / 2.5。  
- Safety 两层；记忆 `MAX_MESSAGES = 20`、`SUMMARY_THRESHOLD = 12`。  
- OpenRouter → SiliconFlow 发生在 W2 部署时，不是 W1 就选对。

### W3 / W4 书稿核对后的硬规则

- 插件路径：`uni-app/src/uni_modules/health-agent-healthkit/`；无 `utssdk/index.uts` stub。  
- W3 只读活动环一小部分；基础代谢 / HRV / 血氧等是 **W4-T10**。  
- `exercise_ids` 是 **W4 迁移**新增，不是 W2 预留。  
- 睡眠按日 upsert **覆盖**；运动按 `workout_id` 去重，手填可与同步并存。  
- 官方 W4 P0 第九项是 SQL 已执行，说明书是 P1；T4 约 19 种运动类型是 P1。
